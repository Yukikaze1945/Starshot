# OCR 文本弹窗启动与闪烁修复

2026-10-21。仅 Debug/源码隔离构建，无安装、推送、发布，无桌面输入或截图，也没有加载 OCR/翻译模型。

## 已定位的问题

1. 原生 app.ready 在编辑器带入 OCR 文本前就显示 WebView，随后才发送 ocr.result。原版本真实隐藏 WebView2 测试中，ready 到查询到正文约相差 46～103 ms；这不是 OCR 推理耗时。
2. 交接时仍有 314 ms 页面入场动画及 CJK webfont 替换。旧版本测试的动画数为 1、fonts 状态为 loading。
3. 每次从结果开始才创建窗口、启动浏览器，未与本次识别并行；环境创建还会在已有浏览器时重复进行。
4. 原生文字预览只 Invalidate，WM_PAINT 可能被已排队的浏览器启动工作延后。
5. 旧窗口复用没有明确 Restore 最小化状态，也不校正可见窗口的异常尺寸或屏外位置。这是“左下角小框”的可疑恢复路径；本轮没有操纵真实桌面复现用户那一次现象，不能将其断言为唯一根因。

## 实现

- 仅在用户真正提交 OCR 操作后创建隐藏编辑器，与该次推理并行。无结果/异常时 preparation lease 清理；并行请求互不提前关闭窗口，不保留空闲隐藏窗口。未在截图选择阶段启动 WebView，也未改轻量选区的 CPU/GDI 路径。
- bootstrap 可以直接带初始 OCR 数据；编辑器首次初始化就有正文。带结果 ID 的 app.ready 在文档提交后的消息任务发送，原生仅在 ID 匹配时交接。迟到的旧 ID 不清空或显示新结果。
- 预备完成的隐藏窗口等待实际正文提交再显示，避免短暂显示原生替身。超过 120 ms 仍未提交才显示 CPU 文字预览；关闭后迟到回调不得恢复窗口。完全冷启动则立即同步绘制原生文字，避免 WM_PAINT 被浏览器初始化抢先。
- OCR 弹窗采用系统字体、防止正文 webfont 替换，取消该弹窗的 page-enter 动画。主题背景与原生预览一致，保留原编辑、翻译、格式和自动复制功能。
- 只借用仍有活跃控制器的浏览器环境，注册表是弱引用且关闭时移除，不增加强引用浏览器环境缓存。
- 最小化窗口先恢复；显示前检查尺寸与当前工作区，可见范围太小/屏外则重建可读尺寸并居中。保留正常打开窗口的用户尺寸。日志记录恢复、尺寸修正和结果到正文提交耗时，不记录正文。
