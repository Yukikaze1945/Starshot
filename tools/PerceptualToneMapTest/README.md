# Perceptual tone-map GPU validation

This harness compiles the production `StarshotPerceptual` and its D2D shader into a small Windows executable. Its assertions use the real GPU effect and independently computed sRGB, OKLab, PQ, and Hermite expectations.

Run `powershell -NoProfile -ExecutionPolicy Bypass -File tools/PerceptualToneMapTest/Run.ps1` from the repository root. The runner uses `dotnet` from `PATH` by default; pass `-Dotnet D:\path\to\dotnet.exe` to select an SDK explicitly. Add `-Performance` to run five 4K cycles. The script redirects build and test output to `build/perceptual-test-build.log` and `build/perceptual-test-run.log`; machine-readable results are written to `build/perceptual-test/validation.json` and `validation.csv`. Performance phases and memory counters are in `performance.csv`.

When a trimmed publish is available, pass its absolute directory with `-PublishedPath D:\path\to\app`. The optional smoke test loads only `Starshot.dll`, invokes the published perceptual renderer on synthetic small bitmaps, and checks SDR white, HDR neutral separation, red, and negative-channel behavior. It does not start the app or capture the desktop.

The test output uses the pinned Ultra HDR DLL at `third_party/libultrahdr/v2.0.2/win-x64/uhdr.dll`, verified against SHA-256 `415EE12ED6E979D1A96A495AFCB634D54FBACF69E5B9E45C95C38793C737384B`. GPU residency counters use `tools/LightweightCaptureTest/GpuMemory.cpp`; if `build/lightweight-native-test/GpuMemory.dll` is absent, the runner builds it with `Build-GpuMemory.ps1`, which requires the Visual Studio x64 C++ toolchain and Windows SDK 10.0.26100.0.

The 4K performance source is a GPU-generated FP16 texture. It includes SDR UI regions, neutral HDR values from 1× to 16×, saturated red/green/blue, signed wide-gamut samples, and UI gradients. The harness reuses it for five measure/render iterations, reads back only one output pixel to flush rendering, samples counters before/after each stage, disposes the source, and samples again after five seconds. These timings cover the GPU measurement and mapping/render completion path; they do not represent end-to-end screenshot capture latency. Memory counters describe process/device residency after disposal and are not expected to reach zero while device resources or caches remain alive. No desktop content is captured.

PNG, AVIF, JXL, and UHDR outputs are encoded through the linked production `ImageSaver` and written only to a GUID-named system temp directory. The harness removes only its own GUID-named directory in `finally`. It does not write image artifacts to Pictures or keep temporary images after a run.

The HDR ramps report both RGB tuples and substantive levels after a 1.5-LSB encoded-luminance tolerance, so dither does not count as retained detail. Pure red must retain at least four substantive levels; other hues report their measured compression, with no large luminance reversals allowed. Special-value outputs must match explicitly sanitized finite inputs byte-for-byte. The logarithmic neutral ramp covers SDR through extreme HDR, and different content parameters must leave the SDR prefix unchanged while actually changing the HDR tail. Published output must match source rendering byte-for-byte. Failures are measured limitations and are not waived just because a channel saturates.
